# v1 acceptance runs

v1 is done when the five use cases in [vision.md](../vision.md#use-cases) pass on a laptop and a VM with a cheap real model, as much of each as possible also runs in CI on the faux model, and no v1 issue is open. This page records the runs of 2026-10-21.

## Setup

- The VM runs `pi-cloud server` as a compiled Bun binary under a systemd user unit, with its built-in `vm` provider. It is the only control plane.
- The laptop (macOS 27) runs `pi-cloud agent --name laptop --server http://127.0.0.1:7421` from source, through `ssh -N -L 7421:127.0.0.1:7420 <vm>`. `/api/environments` lists `laptop` and `vm`, both online.
- The browser reaches the VM's web UI through the same tunnel.
- Models: `github-copilot/gpt-5.3-codex` on the laptop, `google/gemini-3.5-flash-lite` on the VM.
- Before each run: lint 0, typecheck 0, `bun test` and the Playwright e2e all green on the commit under test.

## Results

| Use case                          | Result | CI coverage on the faux model                                                                   |
| --------------------------------- | ------ | ----------------------------------------------------------------------------------------------- |
| 1. Work from anywhere             | Pass   | `web.e2e.ts`: chat, reload replay, terminal                                                     |
| 2. Use the machine the work needs | Pass   | `projects.test.ts`: a Project's threads across two machines and two repositories                |
| 3. Run a Project                  | Pass   | `projects.test.ts`: coordinator wakes once per thread turn, summary without nudging             |
| 4. Survive interruptions          | Pass   | `pi-cloud.test.ts`: restart an interrupted session; `session.test.ts`: interrupted tool results |
| 5. Keep personalization           | Pass   | `session.test.ts`: built-in extensions and codemode; `compiled.test.ts`                         |

### 1. Work from anywhere

- A VM session cloned pi-cloud and got the message "rename the exported function `chatItems` to `transcriptItems` everywhere, don't commit, then show `git diff --stat`". The browser tab was closed right after sending.
- The session went idle 89 seconds later, with no browser open.
- A new browser context with no stored state then showed:
  - The full transcript.
  - The Changes panel: 3 files, 18 insertions and 13 deletions.
  - The terminal: `git diff --stat` gave the same output.

### 2. Use the machine the work needs

- One coordinator turn started three threads:
  - Two on the VM, each checking out only the repository it needed.
  - One on the laptop with `gpt-5.3-codex`.
- The laptop thread's workspace was a worktree of the local checkout plus a clone of the second repository. It read the macOS version and the login keychain path, which only that machine has.
- The VM threads ran at the same time as the laptop thread.

### 3. Run a Project

- **First run: fail.** Thread notices were context only, so the coordinator had no turn to summarize in. It polled with `list_threads` and `sleep`, then ended its turn before the last thread finished.
- **The fix (#85):** each thread turn now starts one coordinator turn. A thread turn that already messaged the coordinator, or that ended in a model error, adds its notice as context only. That stops duplicate turns and a retry loop on an exhausted quota.
- **Runs two and three:** the threads and the coordinator ran out of the Gemini free tier's per-minute quota (429s). These runs found the duplicate-turn and retry-loop problems above.
- **Final run: pass.**
  - The coordinator was on the laptop with `gpt-5.3-codex`. It started three threads across two repositories, two on the laptop and one on the VM, each on its own branch.
  - It got four turns: the user's message, two thread notices, and one thread's `message_coordinator`. That thread's own notice arrived as context only.
  - 84 seconds after the user's message, with no nudge, it wrote one summary with all three results. It made no `read_thread`, `list_threads` or shell calls.
  - The Projects page showed each thread's environment, state and branch.

### 4. Survive interruptions

- **Laptop:**
  - `kill -9` hit the agent and its session processes while a tool ran `sleep 45`.
  - During the two-minute outage, the session showed "running, provider offline". This is by design: a laptop session may still be running while its provider is offline.
  - When the agent came back, the server marked the session interrupted and assigned a new generation. The transcript was kept.
  - The tool result read "The tool was interrupted by a restart and may have partly run".
  - A follow-up question got an accurate account of what had been cut off.
- **VM:**
  - `systemctl --user restart pi-cloud` ran during a `sleep 45` tool call.
  - The session was reassigned and idle again within 8 seconds.
  - A follow-up answer described the interrupted command.
  - The laptop agent's open streams broke during the restart and reconnected without help.

### 5. Keep personalization

- **Laptop, first run:**
  - A session started with no model chose the default from `~/.pi/agent/settings.json` and loaded the user's 25 packages, extensions and skills.
  - It had one tool fewer than `pi` itself: `codemode` was missing.
  - The cause: Pi's CLI loads `codemode`, `tool_search` and MCP as built-in extensions, and SDK hosts must add them. Fixed in #82.
- **Laptop, re-run:** 28 tools hosted and 28 from `pi -p`, the same 53 skills, and a `codemode` script returned 42.
- **VM:**
  - A session with no model used the VM's own default model and settings.
  - #86 makes `codemode` work in the compiled binary, which first failed to find the QuickJS wasm.

## Findings left for later

- The reason a workspace was kept on archive isn't in `GET /api/sessions/<id>`.
- The agent logs a 409 "live events dropped" when it posts for a session that was just archived.
- After a page reload, `#plugin/projects` opens the Project list instead of the open Project.
- Model errors such as a provider's 429 show only in the transcript. The Projects plugin now logs failed thread turns, but sessions in general don't.
